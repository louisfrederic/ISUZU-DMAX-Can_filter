# CAN ID Scanner (Blind ID Blocking Tool)

STM32 firmware for **discovering** which CAN ID drives the speedometer, by blocking one ID at a time and observing which one causes the cluster to lose that piece of information.

## How It Works

Unlike the correction firmware, this variant does not modify any data — it selectively **drops** frames:

1. Every frame received on `CAN1` (vehicle bus) is normally re-transmitted unchanged onto `CAN2` (speedometer).
2. One ID from a fixed candidate list (`blockIDs[30]`) is withheld from forwarding at any given time.
3. A hardware timer (`TIM2`, ~10 s period) advances an index (`z`) through the candidate list, so a new ID is blocked every 10 seconds.
4. By watching the instrument cluster while the firmware cycles through the list, you can identify which ID corresponds to which displayed value (speed, RPM, fuel, etc.) — whichever ID's absence makes a specific gauge/indicator disappear or freeze is the one you're looking for.

This is a quick-and-dirty reverse-engineering aid, not a production tool. The author's own note in the source: this is a "really dirty way to find out your CAN IDs, but a fast one," and fault codes should be cleared afterward since briefly dropping IDs will typically set DTCs on the receiving ECU(s).

## Candidate ID List

`blockIDs[30]` holds the 30 standard IDs to be cycled through, e.g.:

```c
{0x000, 0x191, 0x1c3, 0x378, 0x0c1, 0x0c5, 0x0c9, 0x199, 0x1e5, 0x379,
 0x1c7, 0x1a1, 0x362, 0x1e9, 0x2d1, 0x369, 0x380, 0x1f5, 0x2f9, 0x1cd,
 0x3e9, 0x308, 0x4d5, 0x130, 0x1f1, 0x410, 0x373, 0x3d1, 0x4c9, 0x4c1}
```

(`0x3E9` — the speed ID used by the correction firmware in `Man_in_the_middle_speedometer` — is included here, consistent with having been found this way.)

## Safety Interlock

`GPIO PA15` is configured as a pulled-up input and polled in the main loop. If it reads low, the firmware stops the blocking timer (`HAL_TIM_Base_Stop_IT`) and halts in an infinite loop — a manual kill-switch (e.g. wired to a button or brake signal) to immediately stop interfering with the bus.

## Notes / Caveats

- Only `CAN1 → CAN2` forwarding is implemented; there is no return path from the speedometer back to the vehicle bus in this variant (unlike the bidirectional correction firmware).
- Blocking a live ID will typically trigger fault codes on whichever ECU expected it — clear DTCs with a diagnostic tool after each test run.
- Intended strictly as a bench/diagnostic tool to identify signal IDs before writing targeted correction logic — not for permanent installation.

## File

- `main.c` — STM32 HAL-based entry point; ID-blocking logic lives in `HAL_CAN_RxFifo0MsgPendingCallback`, and the block-index advance lives in `HAL_TIM_PeriodElapsedCallback`. Auto-generated by STM32CubeMX; custom logic is in the `USER CODE` sections.
